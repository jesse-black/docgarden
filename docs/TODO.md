# TODO

This file tracks follow-up tasks and cleanups that came up during planning but are not currently part of an active exec plan.

## Modularize `src/config.rs`

`src/config.rs` holds three distinct concerns that have grown together: TOML deserialization structs, rule-lowering logic (`lower_rules`, `rule_entry_matches`, per-family lowering branches), and per-path policy query methods on `Config`. It is navigable now but will become unwieldy as rule families are added.

**Trigger:** when a second rule family (e.g. headings, links) adds a lowering block and the file grows another ~80 lines, or when a new contributor has visible trouble orienting in the file. At that point extract into `` `src/config/parse.rs` `` (structs + deserialization), `` `src/config/lower.rs` `` (lowering + `rule_entry_matches`), and a thin `` `src/config/mod.rs` `` public surface with `Config` and the query methods. The frontmatter-specific structs and lowering can move to `` `src/config/frontmatter.rs` `` at the same time.

## Clean-code follow-ups

Idiomatic-Rust and architecture cleanups surfaced during the `feat/list` review and a follow-up sweep of the rest of the crate. Address opportunistically when next editing the file in question; the priority bands group items by leverage and risk, not by sequencing.

### High priority

- [ ] **Introduce a `Rule` enum to replace stringly-typed rule names.** Rule identifiers appear as bare string literals in [src/config.rs:495-511](../src/config.rs) (`is_known_rule`, `is_supported_enabled_rule`), in the `disable`/`enable` match arms in [src/config.rs:319-338](../src/config.rs), and in every `rule:` field on `DiagnosticPayload` constructed across [src/lint/rules/file.rs](../src/lint/rules/file.rs), [src/lint/rules/frontmatter.rs](../src/lint/rules/frontmatter.rs), and [src/lint/rules/local_paths.rs](../src/lint/rules/local_paths.rs). Adding a rule today means editing two predicates, two match arms, and the emit-site list. A `Rule` enum with `FromStr`/`serde::Deserialize` would let serde reject typos at parse time, collapse the predicates to `match`, and turn emit-sites into `Rule::PreferLinksForLocalPaths.as_str()`. Highest-leverage change in this list because it touches lint, config, and validation simultaneously and converts a runtime check into a compile-time guarantee.
- [ ] **Collapse `lint::FilePolicy` into `config::EffectiveRulePolicy`.** [src/lint/mod.rs:40-46](../src/lint/mod.rs) defines `FilePolicy` with the same shape as `EffectiveRulePolicy` minus `ignored_rules`, and the only field difference is `backtick_path_severity` vs `unresolved_backtick_path_severity`. [src/lint/mod.rs:59-64](../src/lint/mod.rs) manually unpacks one and repacks the other. Either rename the field on `EffectiveRulePolicy` and pass it through directly (alongside the already-separate `ignored_rules`), or drop `FilePolicy` and pass the four leaf fields. Same parallel-struct smell that `path_prefix` on `DocumentMetadata` resolved.

### Medium priority

- [ ] **Unify `classify_inline_reference` and `classify_link_reference` behind `ReferenceKind`.** [src/lint/references.rs:26-68](../src/lint/references.rs) and [src/lint/references.rs:70-109](../src/lint/references.rs) duplicate ~80% of their structure; the differences are exactly two predicates (backtick rejects on `contains_disallowed_backtick_syntax`; "path-shaped" is `ends_with('/')` vs `contains('/')`). `ReferenceKind` already exists and is threaded into `resolve_candidate` downstream — the same enum can parameterize one classifier. Each function also reconstructs `CandidateReference` three or four times with mostly-identical fields; a small constructor dedupes that. Pin behavior with tests before refactoring since this is a hot lint path.
- [ ] **Mutate `EffectiveRulePolicy` directly in `effective_rule_policy_for_path`.** [src/config.rs:302-355](../src/config.rs) builds five parallel locals (`ignored_rules`, `backtick_severity`, `prefer_links`, `max_tokens`, `max_lines`) inside the loop, then assembles them into an `EffectiveRulePolicy` whose fields are the same five. Initialize `EffectiveRulePolicy::default()` and mutate it in the loop body — the locals just rename what's already on the struct.
- [ ] **Extract `Config::load` orchestration steps.** [src/config.rs:218-292](../src/config.rs) is a 75-line method that does config-path discovery, file reading, TOML parse, default-toml fallback, scope-dir validation, extension/special-filename merging, include-pattern fallback, rule lowering, and final assembly. Pull `resolve_config_path`, `parse_or_default`, and `merge_extensions` (or similar) into private functions so `Config::load` reads as orchestration. Lower-friction first cut at the broader `src/config.rs` modularization captured separately above.
- [ ] **Drop `#[cfg(test)]`-fenced fields from `CombinedFieldStats`.** [src/score.rs:10-22](../src/score.rs) carries `name`, `path_prefix`, `description`, and `pseudo_sum_total_term_freq` only when compiled under `cfg(test)`, so the production type has a different shape than the test type. The dependent assertions in [src/score.rs:387-405](../src/score.rs) check that the BM25 derivation matches its own formula rather than externally observable behavior. Either drop those tests, or expose the derived numbers through stable `pub(crate) fn` accessors that don't bifurcate the struct.
- [ ] **Factor a comment/blank-line skip helper in the YAML parser.** [src/frontmatter.rs:108-272](../src/frontmatter.rs) repeats the same prologue across `parse_yaml_block`, `parse_block_value`, `parse_nested_mapping`, and `parse_sequence`: trim the line, skip if empty or starts with `#`, then recompute leading-whitespace indent. A helper like `fn skip_or_indent(line: &str) -> Option<(usize, &str)>` returning `None` for skip lines unifies the prologue and removes four near-identical guards.

### Low priority

- [ ] **Drop `LintResult` in favor of returning `Vec<Diagnostic>`.** [src/lint/mod.rs:24-26](../src/lint/mod.rs) wraps a single `Vec<Diagnostic>` field; the only caller in [src/cli.rs:319](../src/cli.rs) immediately unwraps it via `result.diagnostics.extend(...)`. Have `lint_file` return `Result<Vec<Diagnostic>>` directly. Same single-field-options-struct anti-pattern as the removed `ListRenderOptions`.
- [ ] **Take `&mut WalkState` in `emit_finding`.** [src/lint/mod.rs:134-163](../src/lint/mod.rs) bundles four fields into `WalkState`, then `emit_findings` immediately re-explodes them into a 5-argument call to `emit_finding(state.diagnostics, state.ignored_rules, state.mode, state.edits, finding)`. Have `emit_finding` accept `&mut WalkState` and `Finding` and let `emit_findings` just iterate.
- [ ] **Replace double-pattern-matching in lint node rules.** [src/lint/rules/local_paths.rs:18-22](../src/lint/rules/local_paths.rs) already filters on `Node::InlineCode(_)` and `Node::Link(_)` before dispatch, but [src/lint/rules/local_paths.rs:29-34](../src/lint/rules/local_paths.rs) and [src/lint/rules/local_paths.rs:92-97](../src/lint/rules/local_paths.rs) re-check the variant via `let Some(inline) = (match node { Node::InlineCode(inline) => Some(inline), _ => None }) else { ... };`. Either pass the inner `&InlineCode`/`&Link` from the dispatcher, or use idiomatic `let Node::InlineCode(inline) = node else { return Ok(Vec::new()); };`.
- [ ] **Flatten `Option<Vec<T>>` config fields to `Vec<T>` with `#[serde(default)]`.** [src/config.rs:54-72](../src/config.rs) declares `pub disable: Option<Vec<String>>` and `pub enable: Option<Vec<String>>`, and [src/config.rs:404-405](../src/config.rs) immediately calls `.unwrap_or_default()` on both. There is no semantic difference between an absent field and an empty list; drop the `Option` wrapper and let serde default to `Vec::new()`.
- [ ] **Avoid eager `unwrap_or` in `infer_repository_root`.** [src/root.rs:38-39](../src/root.rs) writes `.unwrap_or(std::env::current_dir()?)`, which always evaluates `current_dir()` even when `common_ancestor` returned `Some`. Replace with a `match` so the syscall only fires on the fallback path.
- [ ] **Collapse repeated `contains`/`starts_with` chains in the YAML parser.** [src/frontmatter.rs:289-297](../src/frontmatter.rs) `has_unsupported_key_chars` makes seven full passes over the key when one `key.chars().any(|ch| matches!(ch, '{' | '}' | '[' | ']' | '&' | '*' | '!'))` would do. [src/frontmatter.rs:321-332](../src/frontmatter.rs) `parse_inline_scalar` does the same with seven `value.starts_with(...)` checks; replace with `matches!(value.chars().next(), Some('{' | '[' | '&' | '*' | '!' | '|' | '>'))`. Cosmetic but the disallowed set becomes visible at a glance.
